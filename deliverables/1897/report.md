# FURPS+: краткий анализ учебного описания

Макаров Артем Александрович · 3427А

## Исходное описание
Отдельный текст требований не приложен. Учебный пример: прокат должен резервировать прибор, показывать срок, переживать перезапуск, отвечать за две секунды, позволять менять тариф и обмениваться JSON.

| Требование | FURPS+ |
|---|---|
| Резервировать свободный прибор без пересечения интервалов | F |
| Показывать срок рядом с подтверждением | U |
| Сохранять подтверждённую бронь после перезапуска | R |
| p95 ответа ≤ 2 с при 50 пользователях | P |
| Изменять тариф в отдельном модуле с тестами | S |
| Обмен JSON UTF-8 по API v1 | + |

## Приоритеты
1. Корректность брони: двойное резервирование делает продукт непригодным.
2. Сохранность данных: потерянная бронь нарушает договорённость с пользователем.
3. Понятный срок снижает ошибки выбора.

- Численные показатели предложены для учебного стенда.
- Документация поддерживает S, а + обозначает ограничения, не только документацию.
- Приёмка: конкурентная бронь, перезапуск, нагрузочный замер и смена тарифа.
