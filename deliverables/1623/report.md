# Selenium, JUnit и pytest для проекта мастерской

Макаров Артем Александрович · 3427А

## Сравнение
| Критерий | Selenium | JUnit | pytest |
|---|---|---|---|
| Основная роль | Управление браузером | Тестовый фреймворк JVM | Тестовый фреймворк Python |
| Автоматизируемые проверки | Сквозные сценарии веб-интерфейса | Модульные и интеграционные Java-тесты | Модульные, интеграционные и API-тесты Python |
| Простота | Нужно управлять ожиданиями и состоянием браузера | Удобен в JVM-проекте | Обычные функции и assert, fixtures |
| Гибкость | Несколько браузеров и языковых привязок | Расширения, параметризация | Плагины, параметризация, fixtures |
| Сообщество | Официальная документация, проект WebDriver | Документация и расширения JVM | Документация и плагины |
| Стоимость | Open source; инфраструктура браузеров отдельно | Open source; CI отдельно | Open source; CI отдельно |
| Ограничение | Медленнее и хрупче чистого unit-теста | Нужен JVM-контекст | Сам по себе не управляет браузером |

## Обоснование
Для Python-сервиса проката основой выбран pytest: он соответствует языку и позволяет быстро проверять расчёт и ограничения бронирования. Selenium дополняет его несколькими сквозными сценариями, например подтверждением брони через форму. JUnit уместен для отдельного Java-клиента, но переносить в него Python-тесты нет смысла.
Простота влияет на скорость добавления проверок, гибкость — на интеграции, поддержка — на доступность документации и исправлений, стоимость — на бюджет выполнения. Размер сообщества численно не сравнивался. Это выбор по архитектуре проекта, а не универсальный рейтинг.
