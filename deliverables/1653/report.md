# Задачи ремонтной бригады — классификация FURPS+

Макаров Артем Александрович · 3427А

## Введение
Задачи ремонтной бригады. FURPS+ разделяет функции (F), удобство (U), надёжность (R), производительность (P), сопровождаемость (S) и дополнительные ограничения (+). Безопасность поведения относится к F, конкретные ограничения шифрования — к +. S не означает стоимость, а + не сводится к документации. Функциональное требование задаёт действие системы; нефункциональное — измеримое качество или ограничение. Числа ниже предложены автором для учебной приёмки, а не установлены стандартами. Полная нормативная экспертиза не заявляется.

## Основная часть
| Компонент FURPS+ | Соответствующее требование | Проверка |
|---|---|---|
| F | R1: Создание, редактирование и архивирование объекта «задача» с историей | Архив скрыт из активного списка, история доступна |
| F | R2: Назначение исполнителя, срока и статуса с проверкой разрешённых значений | Срок и исполнитель сохраняются, неверный статус отклоняется |
| F | R3: Пользователь видит свои объекты; оператор видит объекты своей рабочей группы | Запрос чужого ID возвращает отказ |
| U | R4: Все действия основной формы доступны клавиатурой, фокус виден | Пройти сценарий без мыши |
| U | R5: 4 из 5 новичков завершают основной сценарий за 4 минуты без помощи | Наблюдение по одинаковому сценарию |
| R | R6: Повтор запроса с одним ключом операции не создаёт второй объект | Отправить один ключ 3 раза, проверить одну запись |
| R | R7: Подтверждённые изменения переживают перезапуск; RPO 12 ч, RTO 90 мин при аварии | Перезапуск и восстановление тестовой копии |
| P | R8: p95 поиска ≤ 1.8 с при 75 пользователях и 30 000 записях | 10 минут нагрузки после 2 минут прогрева |
| P | R9: Экспорт 5000 записей завершается за 20 с на стенде 2 CPU, 4 ГБ RAM | Замер времени и числа экспортированных строк |
| S | R10: Правила статусов выделены в модуль; каждый разрешённый и запрещённый переход имеет тест | Изменить правило и выполнить регрессию |
| S | R11: Документация содержит запуск, резервирование и восстановление; новый участник запускает стенд по ней | Контрольный запуск без устных подсказок |
| + | R12: HTTP API v1, JSON UTF-8, время ISO 8601 с поясом; TLS при передаче | Контрактные тесты и проверка конфигурации |
## Заключение
Приоритет имеют корректное изменение состояния, разграничение доступа и восстановление. Скорость и удобство измеряются отдельно. Сопровождаемость поддерживается изоляцией правил и проверяемой документацией.
