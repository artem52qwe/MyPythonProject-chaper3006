## Функциональность
| Требование | Компонент | Приёмка |
|---|---|---|
| Пассажир выбирает начало, одну остановку и конец; подтверждает оценку цены | F | Проверить маршрут с остановкой и без неё |
| Водитель получает только назначенную поездку | F | Чужой ID отклоняется сервером |

| API v1, TLS, геолокация только с разрешением | + | Ручной адрес работает без разрешения |

## Нефункциональные требования
Надёжность: после разрыва сети клиент запрашивает статус по прежнему ID. Производительность измеряется после прогрева, ошибки внешнего маршрутизатора учитываются отдельно. Поддержка: инструкция описывает диагностику зависшей поездки и безопасное повторение запроса. Стоимость — ограничение бюджета проекта, а не отдельная буква FURPS+. Учебный бюджет инфраструктуры ограничен согласованным владельцем лимитом; неизвестная сумма не выдумывается.

## Структура спецификации
Назначение → роли → маршруты и отмена → удобство → устойчивость → нагрузка → сопровождение → ограничения → приёмка. Приведённые пороги предварительные; продукт не развёрнут и оплата не выполнялась.
